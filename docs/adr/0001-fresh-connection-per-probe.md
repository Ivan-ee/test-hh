# Свежее соединение на каждую пробу

Дефолтный HTTP-агент Node держит keep-alive: из 10 последовательных проб реальный DNS/TCP/TLS был бы только у первой, у остальных connect-фаза ≈ 0 — длительности проб стали бы несопоставимы между собой, а «среднее время запроса» смешало бы два разных режима. Решение: каждая Probe измеряется по свежему соединению и закрывается после ответа — пофазные тайминги каждой пробы честные и сопоставимые.

## Considered options

- Keep-alive-агент: реалистичнее для браузерного сценария повторных загрузок, но измеряет «тёплый» путь и смешивает семантику проб.
- Прогревочный запрос + серия по тёплому соединению: добавляет второй режим и усложняет интерпретацию результатов без запроса пользователя.

## Consequences

- Средняя скорость ниже, чем при повторном скачивании по готовому соединению; это осознанно — измеряется полный путь до цели.
- CDN-кэш всё равно может отдавать тело быстрее на повторных пробах; это свойство цели, а не ошибка измерения (упоминается в README).
