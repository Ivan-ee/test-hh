# ⚡ netspeed

Консольный тулзамер скорости скачивания (тестовое задание). Принимает адрес, делает **10 последовательных запросов**, дожидается **полного ответа** на каждый, считает **среднее время запроса**, **общий объём** и **скорость скачивания** — с живым TUI, пофазными таймингами и динамическими единицами.

## Демо (реальный вывод)

В терминале запросы идут один за другим, и по мере каждого запроса данные появляются сразу — спиннер, прогресс-бар, мгновенная скорость и спарклайн обновляются вживую:

## Возможности

- **10 последовательных запросов** по умолчанию (`-n` меняет), каждый полностью скачивается;
- **среднее время запроса** + min / median / max по всем пробам;
- **общий объём** и **итоговая скорость** в динамических единицах + строка в Mbps;
- **валидация цели** до замера (preflight): корректный URL, доступность, сервер реально отдаёт тело;
- **пресеты**: «Яндекс-картинка» (~3.5 MB JPEG с CDN Яндекса) и «Sintel movie» (~1.1 GB с сервера Blender Foundation) + своя ссылка — аргументом или в интерактивном меню;
- **пофазный разбор**: DNS → TCP → TLS (connect), TTFB, download — по каждому запросу;
- **живой TUI** на [ink](https://github.com/vadimdemedes/ink) и **plain/JSON режимы** для скриптов и CI;
- vitest-тесты, ESLint, GitHub Actions CI.

## Установка

Требования: **Node.js ≥ 24** (проверено на актуальных LTS: 24 и 26).

```bash
git clone https://github.com/Ivan-ee/test-hh.git
cd test-hh
npm ci
npm run build
node dist/cli.js --help
```

Для разработки можно запускать без сборки: `npm run dev -- <url>`.

## Запуск

```bash
node dist/cli.js                          # интерактивное меню: пресеты или своя ссылка
node dist/cli.js https://example.com/big.mp4   # замер по ссылке
node dist/cli.js --preset yandex-image    # пресет «Яндекс-картинка»
node dist/cli.js --preset sintel-video -n 3    # пресет «большое видео», 3 запроса
node dist/cli.js --json -n 5 <url>        # машинно-читаемый JSON (для скриптов)
```

| Флаг                      | Значение                                                          | По умолчанию |
| ------------------------- | ----------------------------------------------------------------- | ------------ |
| `-n, --requests <count>`  | число последовательных запросов                                   | `10`         |
| `-t, --timeout <seconds>` | лимит времени на один запрос; `0` — ждать полный ответ без лимита | `0`          |
| `-p, --preset <id>`       | встроенная цель: `yandex-image` \| `sintel-video`                 | —            |
| `--json`                  | результат одним JSON-документом в stdout, без TUI                 | —            |
| `-V, --version`           | версия                                                            | —            |

Клавиши в интерактивном меню: `↑/↓` — выбор, `Enter` — старт, `Esc` — назад, `Ctrl+C` — выход.

## Единицы измерения

- **Размеры и скорости — динамические, десятичные (1000)**: `B → kB → MB → GB` и `B/s → kB/s → MB/s → GB/s`. Единица выбирается автоматически под величину: маленькая картинка покажет `kB`/`MB`, большое видео — `MB`/`GB`. Так пользователь всегда видит число «человеческого» порядка — и в live-панели, и в итогах.
- **Вторая строка — фиксированные `Mbps`** (десятичные биты, байты × 8): словарь спидтестов и ISP-тарифов, с которыми пользователь сравнивает результат.
- Почему десятичные, а не двоичные: это однозначно — «KB» в двоичной системе означало бы 1024 байта и требовало бы меток `kiB/MiB`; десятичные `kB/MB` (1000) используют curl и wget по умолчанию, и они совпадают с тем, что показывают браузеры и спидтесты.

## Как измеряется (методология)

- **Каждый запрос — по свежему TCP/TLS-соединению** ([ADR 0001](docs/adr/0001-fresh-connection-per-probe.md)). Иначе keep-alive дал бы честные DNS/TCP/TLS только на первом запросе из десяти, и «среднее время запроса» смешало бы два разных режима.
- **«Время запроса»** — от старта запроса до последнего байта тела (`performance.now()`): задание требует дожидаться полного ответа.
- **Фазы** одного запроса: DNS → TCP → TLS (суммарно connect) → TTFB (от установленного соединения до заголовков) → download (от заголовков до последнего байта). Сегменты не пересекаются и в сумме дают полное время.
- **Скорость запроса** = байты / полное время запроса (аналог `curl speed_download`); **итоговая** = Σ байт / Σ времени успешных запросов.
- **Median как главная оценка**: первый запрос всегда «холодный», median устойчив к таким выбросам; `avg`, `min`, `max` — рядом.
- **Провода честные**: мы не просим сжатие (`Accept-Encoding: identity`, [ADR 0002](docs/adr/0002-node-builtin-http.md)), поэтому байты — ровно то, что прошло по сети.
- **Ошибки не останавливают серию**: неудачный запрос помечается `✘` с причиной, итог считается по успешным.
- CDN может отдавать повторные запросы быстрее (кэш на границе) — это свойство цели, а не ошибка замера; в README это указано честно.

## Режимы вывода

- **TTY** — живой TUI (ink): статическая зона накапливает завершённые запросы, живая обновляется ~10 раз в секунду;
- **pipe/CI** — plain-режим: по строке на завершённый запрос + итог (без перерисовки);
- **`--json`** — один JSON-документ: все пробы, фазы, статистика.

## Exit codes

| Код | Значение                                            |
| --- | --------------------------------------------------- |
| `0` | серия завершилась, был хотя бы один успешный запрос |
| `1` | ошибка использования или цель не прошла проверку    |
| `2` | все запросы завершились ошибкой                     |
